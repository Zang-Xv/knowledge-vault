# 智能体架构

关于智能体应用当中的架构设计流程
我看到一个文章讲述了金融智能体产品设计过程中采用的架构变化
这使我产生一些问题：智能体架构都是什么样的？智能体产品如何使用他们？

## 文章主要内容

文章当中简单介绍了一些智能体产品设计的背景
要求做一个金融复盘智能体，给用户提供以行业概念为主体的可溯源的复盘报告

坐着首先使用了 workflow 式的架构，通过访谈了解了大致功能需求后，拆解形成了一个获取信息以及处理信息的流程。

```text
顶层意图判断 → 实体拆分和映射 → 泛指大类图谱映射为子行业并拆分问句 → 子问句意图判断 → 槽位提取 → 不同意图对应固定工具流程 → LLM 生成最终结果
```

这个拆解其实非常自然，这是产品的常见问题处理路径，将模糊的功能需求通过常见的操作流程固定下来，然后用智能和机械填充到路径当中去。

但是作者提到这个流程不是特别合适，它难以处理复合的复杂的问题，流程中的模板感非常严重，没有复盘分析的感觉。于是更换称为了 Plan 架构。说实在的这里我不是很理解，不过暂且先搁置。

根据可实现能力，封装出各种独立工具，让智能体先针对问题动态决定路径和流程计划，再一步步调用独立工具完成。

我们可以看到这其实很好懂，workflow 似乎就是对流程的自动化和智能填充。而 Plan 架构则类似于现在的 SKILL，让智能体自己决定要怎么完成，充分发挥模型的创造性。

但是我还是有些难以理解这篇文章的用意。似乎都是非常简单的问题拆解和实现方法，我没能看懂作者在这个过程中具体踩坑的原因和思路的转变。而且其中的黑话和表达我还难以领会，文章能看，看起来很厉害，但是实际难以体会其中内容。我还是对于 ai 如何应用于实际生产没有具体的想象能力。
